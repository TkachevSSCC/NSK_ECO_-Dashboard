# Описание программы

**Обозначение:** НСКЭКО.002.ОП
**Наименование:** «NSK Eco Dashboard»
**Версия:** 1.0, проект

## 1. Общие сведения

Программа является веб-приложением с клиентом на React/Vite и серверным API на FastAPI. Клиент получает данные станций и настройки через REST, текущие метрики — через WebSocket. PostgreSQL используется для сущностей станций и связанных данных; Redis и Celery обеспечивают предусмотренные фоновые и временные функции.

## 2. Функциональное назначение

Программа отображает состояние сети экологических станций и предоставляет средства демонстрационного управления моделью сетевого обмена. Основные данные станции: идентификатор, координаты, тип, заряд батареи, PM2.5, PM10 и признак превышения. Устройства с нулевым зарядом исключаются из активных расчётов.

Основные функции интерфейса:

- карта и список/группировка станций;
- просмотр метрик и журнала событий;
- изменение состава сети, параметров передачи, буфера и весов сообщений;
- просмотр кластерных и нагрузочных сценариев;
- моделирование загрязнения;
- отображение тепловой карты, подбор зон установки и экспорт PDF;
- панель интеграции с СИГМА.

Набор доступных элементов зависит от версии интерфейса и конфигурации окружения.

## 3. Логическая структура

| Подсистема | Реализация | Назначение |
|---|---|---|
| Клиент | `frontend/src` | Интерфейс оператора, карта, графики, сценарии и отчёты |
| REST API | `backend/app/api/v1` и `backend/app/integrations/sigma/api.py` | Операции со станциями, тестовыми функциями и СИГМА |
| Сервисный слой | `backend/app/services` | Операции с данными станций, кластеризацией и пользователями |
| Расчёт метрик | `backend/app/metrics` | Сетевые метрики, цикл обновления и публикация состояния |
| Хранилище | `backend/app/db`, PostgreSQL | Модели и доступ к постоянным данным |
| Очереди/состояние | `backend/app/core/redis_client.py`, Celery, Sigma outbox | Временное состояние и фоновые задачи |
| Интеграция | `backend/app/integrations/sigma` | Формирование, очередь и отправка событий платформе |
| Исходные данные карты | `backend/app/data` и `data` | Геоданные и наборы исходных данных |

## 4. Входные и выходные данные

### 4.1. Входные данные

- записи станций из PostgreSQL;
- пользовательские команды интерфейса;
- координаты, значения PM2.5/PM10 и параметры сценариев;
- конфигурация окружения backend;
- географические маски и данные, поставляемые с проектом;
- ответы внешних сервисов, если соответствующие интеграции доступны.

Достоверность, единицы и метод получения исходных измерений определяются источником данных и не гарантируются самим интерфейсом.

### 4.2. Выходные данные

- HTML-интерфейс и визуализация карты;
- JSON-ответы REST API;
- поток JSON-метрик WebSocket;
- PDF-отчёт тепловой карты;
- события интеграции СИГМА и диагностические сообщения.

## 5. Интерфейсы

Основной REST-префикс управления станциями — `/stations`. Доступны операции получения, добавления и удаления станций, управления зарядом и загрязнением, настройки режима передачи и буфера, получения масок/дорог, кластерных представлений и сценариев нагрузки. Интеграция СИГМА предоставляет `/sigma/status`, `/sigma/test`, `/sigma/events` и `/sigma/dead`. Метрики доступны по WebSocket `/ws/metrics`. Полная схема запросов конкретной сборки публикуется FastAPI в `/docs`.

Для клиентского dev-сервера конфигурация Vite проксирует API-запросы к локальному backend. В production требуется веб-сервер, раздающий `frontend/dist` и маршрутизирующий API и WebSocket к backend.

## 6. Используемые технические средства

Python 3.10+, Node.js/npm, PostgreSQL, Redis, современный браузер. Версии библиотек зафиксированы в `backend/app/requirements.txt` и `frontend/package-lock.json`.

## 7. Запуск

Порядок установки и запуска приведён в [руководстве программиста](05-руководство-программиста.md). Для разработки обычно используются адреса frontend `http://localhost:5173`, API `http://127.0.0.1:8000`, Swagger UI `http://127.0.0.1:8000/docs`.
