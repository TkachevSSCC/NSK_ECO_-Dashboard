# Руководство программиста

**Обозначение:** НСКЭКО.005.РП
**Наименование:** «NSK Eco Dashboard»
**Версия:** 1.0, проект

## 1. Требования к среде

- Python 3.10+ и pip;
- Node.js и npm;
- PostgreSQL;
- Redis для фонового брокера и функций, использующих Redis;
- Git для получения исходного кода.

## 2. Установка

### 2.1. Backend

В каталоге `backend` создайте виртуальное окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r app/requirements.txt
```

В Windows PowerShell активируйте `.venv\Scripts\Activate.ps1`.

Создайте `backend/.env` по образцу `backend/.example.env`. Заполните подключение к PostgreSQL и Redis. Создайте базу данных и примените миграции из каталога `backend`:

```bash
alembic upgrade head
```

Не помещайте реальные пароли и ключи в исходный код, клиентскую часть или Git.

### 2.2. Frontend

```bash
cd frontend
npm install
```

## 3. Запуск

Запустите API из каталога `backend`:

```bash
.venv/bin/uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Запустите frontend в отдельном терминале:

```bash
cd frontend
npm run dev
```

Для фоновых задач при необходимости запустите отдельные процессы:

```bash
cd backend
.venv/bin/celery -A app.core.celery_app.celery worker --loglevel=info -P solo
.venv/bin/celery -A app.core.celery_app.celery beat --loglevel=info
```

Swagger UI backend доступен по `http://127.0.0.1:8000/docs`. Скрипт `start.ps1` предназначен для Windows и имеет собственные предположения о расположении виртуального окружения и служб; перед использованием проверьте его настройки.

## 4. Конфигурация

Обязательные группы настроек `backend/.env`:

| Группа | Назначение |
|---|---|
| `DB_USER`, `DB_PASS`, `DB_HOST`, `DB_PORT`, `DB_NAME` | Подключение к PostgreSQL |
| `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND` | Брокер и результаты Celery |
| `SIGMA_*` | Необязательная интеграция с СИГМА, лимиты и повторы |

Полный список и значения по умолчанию приведены в `.example.env`. Интеграция СИГМА не активируется без требуемых учётных параметров и включающего флага. Тестовая отправка управляется `SIGMA_TEST_ENABLED`.

## 5. Интерфейсы backend

- `GET/POST /stations/...` — чтение и управление станциями, сценариями, буфером, весами сообщений, масками и кластерной визуализацией.
- `GET /stations/load_scenarios` — расчёт вариантов нагрузки.
- `WS /ws/metrics` — JSON-снимок текущих метрик с интервалом расчётного тика.
- `GET /sigma/status` — статус интеграции.
- `POST /sigma/test` — тестовая отправка при разрешённой конфигурации.
- `GET /sigma/events` — последние события с фильтрами `processed`, `level`, `limit`.
- `GET /sigma/dead` — элементы dead-letter-очереди.
- `GET /docs` — интерактивная спецификация OpenAPI.

Точный перечень параметров и кодов ответа следует проверять в OpenAPI именно развёртываемой версии.

## 6. Проверки и сборка

```bash
cd backend
.venv/bin/python -m compileall -q app
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

```bash
cd frontend
npm run lint
npm run build
```

Smoke-тест интеграции СИГМА с локальным мок-сервисом запускается из backend согласно инструкциям в корневом README. Для production-развёртывания соберите frontend командой `npm run build`; содержимое `frontend/dist` отдаётся веб-сервером, который также проксирует REST и WebSocket на FastAPI.

## 7. Сопровождение и диагностика

- Проверяйте журналы Uvicorn, Celery, PostgreSQL и Redis.
- При ошибке импорта сначала проверьте активное окружение и версии зависимостей.
- При ошибке миграции проверьте DSN, доступность БД и текущую ревизию Alembic.
- Для отказов доставки СИГМА проверьте сетевую доступность, идентификаторы источника, allowlist и очередь недоставленных событий.
- Текущий цикл метрик и интеграционный воркер рассчитаны на один процесс backend; горизонтальное масштабирование требует отдельного проектирования фоновых задач.

## 8. Эксплуатационные данные

Пути, форматы резервного копирования, сроки хранения и процедуры восстановления должны быть определены администратором целевой инсталляции. В репозитории нет утверждённого регламента резервного копирования.
