# Программа и методика испытаний

**Обозначение:** НСКЭКО.006.ПМИ
**Наименование:** «NSK Eco Dashboard»
**Версия:** 1.0, проект

## 1. Объект испытаний

Веб-приложение «NSK Eco Dashboard», включая frontend, backend API и настроенные хранилища. Испытываемая версия и идентификатор сборки фиксируются в протоколе.

## 2. Цель и условия испытаний

Цель — подтвердить установку, запуск и выполнение основных пользовательских функций в согласованном окружении. Требуются Python 3.10+, Node.js/npm, доступные PostgreSQL и Redis, установленная конфигурация приложения и современный браузер. Для испытаний СИГМА используется тестовый контур либо локальный мок; реальные секреты в протокол не включаются.

## 3. Средства контроля

Браузер, журналы backend и фоновых процессов, Swagger UI, средства проверки WebSocket, команды сборки/линтера frontend и unittest backend. Конкретные версии ОС, БД, браузера и ПО записываются в протокол.

## 4. Порядок проведения

Перед началом установить зависимости, применить миграции и запустить требуемые процессы. Для каждого пункта зафиксировать шаги, ожидаемый результат, фактический результат, статус и диагностические материалы. При обнаружении дефекта зафиксировать запрос/ответ без секретов.

## 5. Проверки

| № | Проверка | Методика и ожидаемый результат |
|---:|---|---|
| 1 | Импорт и запуск backend | Выполнить `python -m compileall -q app` и запустить Uvicorn; приложение стартует без фатальной ошибки |
| 2 | Запуск frontend | Выполнить `npm run lint` и `npm run build`; команды завершаются успешно |
| 3 | Доступность API | Открыть `/docs`; Swagger UI доступен, маршруты приложения перечислены |
| 4 | Получение станций | Выполнить `GET /stations`; сервер возвращает JSON-список либо корректный пустой список согласно данным среды |
| 5 | Контракт станции | Для записи проверить поля `id`, `type_st`, `battery_life`, `latitude`, `longitude`, `PM_2_5`, `PM_10`, `overTLV`; числовые координаты должны находиться в географическом диапазоне |
| 6 | Изменение состояния | Добавить тестовую станцию или изменить доступный сценарный параметр; проверить ответ API и отражение результата в интерфейсе; затем восстановить исходное состояние |
| 7 | Метрики | Подключиться к `/ws/metrics`; получать JSON-обновления примерно раз в секунду при доступной БД и работающем backend |
| 8 | Прогноз сценариев | Вызвать `GET /stations/load_scenarios`; получить набор сценариев и числовые показатели без побочных изменений состояния |
| 9 | PDF-отчёт | В интерфейсе построить тепловую карту и выполнить экспорт; браузер получает непустой PDF-файл |
| 10 | СИГМА не настроена | При отсутствии обязательных параметров проверить статус; API явно сообщает о ненастроенной/выключенной интеграции, основная панель остаётся доступной |
| 11 | СИГМА с мок-сервисом | Запустить предусмотренный smoke-тест; форматирование и доставка тестовых/экологических событий соответствуют контрактным тестам |
| 12 | Backend unit tests | Выполнить `python -m unittest discover -s tests -p 'test_*.py'`; все тесты завершаются успешно |

Операции, изменяющие данные или загрязнение, проводить на тестовой базе либо после создания резервной копии.

## 6. Критерии приёмки

Испытание считается пройденным, если обязательные проверки 1–10 и 12 завершились ожидаемым результатом, а проверка 11 пройдена при заявленной в составе поставки интеграции СИГМА. Все отклонения зарегистрированы и согласованы. Нагрузочные показатели, производительность и безопасность требуют отдельных критериев, которые заказчик должен задать до соответствующих испытаний.

## 7. Протокол

В протокол включить: обозначение и версию Программы; дату; состав комиссии; характеристики стенда; версии зависимостей; исходные данные; таблицу результатов; список дефектов; заключение и подписи ответственных лиц.
